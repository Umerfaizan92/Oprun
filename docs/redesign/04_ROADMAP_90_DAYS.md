## Release sequence and measurement

1. Ship the additive foundation only after source preservation, security tests and full responsive CI pass. Verify exact main/deployed SHA on the existing Render service.
2. With owner-arranged consent, validate navigation and enquiry-to-invoice tasks with 3–5 subscribers. Record task time, errors, unsuccessful searches and support confusion; do not contact them without instructions.
3. Prioritise actual Inbox and customer timeline data mapping next. Publish a migration dry-run report before any canonical record cutover.
4. Gate each provider by actual granted scopes, API availability, review, billing and acknowledgement. Keep unsupported uploads and paid spend disabled until separately implemented and tested.
5. Android/iOS signing, device tests and store review remain separate from a successful web deployment. Existing install, deletion and independent Operator sign-in safeguards must survive every release.
