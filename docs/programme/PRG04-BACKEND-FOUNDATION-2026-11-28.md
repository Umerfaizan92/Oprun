# PRG-04 backend foundation readiness register

Read-only source review at audit baseline 85f722449774a43d1d16f19ad21e6b9236bf8c05. This register defines foundation exit evidence for later reserved implementation.

| Foundation | Existing evidence | Required before adoption |
| --- | --- | --- |
| Adaptive onboarding | `src/onboarding-interview.js` has tenant-scoped resumable answers and completion. `src/onboarding-questions.js` and `src/onboarding-proposal.js` generate a proposal and record choices and consent. Approval currently permits owner, admin and super-admin. | Pin question and proposal versions and the full jurisdiction/industry/config context in the approved revision. Demonstrate restart, concurrent edits, stale approval and permission revocation. Resolve the owner-only approval requirement for the future workflow before PRG-05 adopts the current role matrix. |
| Activity packs | `src/industry-registry.js` supplies industry metadata, documents, default modules and source references. Proposal generation supplies service, stage and template choices. | Define a pack ID/version and source matrix, composition order, required versus optional items, explicit conflicts and legacy defaults. Demonstrate that mixing packs cannot silently broaden authority, replace customised content or trigger a provider operation. |
| Jurisdiction configuration | `src/country-rules.js`, the industry source lookup and proposal context supply country/state and ruleset inputs. | Store an effective-dated rule revision with source and review date, separate legal entity and service jurisdiction, and represent unknown/unsupported cases explicitly. Validate local administrative, privacy and tax assumptions with authorised reviewers. PRG-06 remains paused. |
| Server-side permissions | `src/staff-access.js`, `src/module-rules.js` and route role guards provide independently useful controls. The tenant comes from the server session. | Inventory feature/action routes and worker entry points, with company capability intersected with membership, role ceiling and special data scopes. Verify disabled features on direct calls and background execution, revoked membership, cross-tenant identifiers, and operator/support separation. A hidden navigation item provides no permission evidence. |
| Versioned workspace configuration | Proposal records retain decisions and consent, while apply updates mutable `modules_json` and profile fields. | Require immutable tenant revisions, expected-revision compare-and-set, a transactional current pointer, audit attribution and a recovery revision that preserves history and customised values. Test legacy reads, conflicting writes, idempotent apply and safe rollback. A consent-text version alone does not establish effective configuration history. |

PRG-04 owns the foundation contracts and T-274 design. PRG-05 adaptive implementation and PRG-07 Operator Console remain reserved. PRG-09 follows the release gates.
