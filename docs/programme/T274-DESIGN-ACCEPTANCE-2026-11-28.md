**Design accepted with execution gates open.** The current fail-closed contract was independently accepted at a88d777605480fba58aeff2e07f8981773b6a7bc. The proposed scoped key change has no implementation or execution approval.

| Gate | Acceptance evidence and preconditions |
| --- | --- |
| Schema and scope | The existing global uniqueness contract must remain readable until cutover. Inventory actual SQLite version, complete DDL, foreign keys, indexes, indexes created implicitly by constraints, triggers, views and all producers/consumers. Use tenant uniqueness over organisation, type and key, and platform uniqueness over type and key when organisation is null. A null key continues to bypass deduplication. Preserve literal keys, empty-value behaviour, IDs, leases, status, timestamps, payloads, results and domain references. Map every key lookup, including the automation resume prefix query in `src/automation/engine.js`. Before permitting scoped duplicates, require every writer and reader to declare compatible schema capability. |
| Active workers | Source starts the main and studio edit queues in `src/server.js` unless their relevant gates prevent it. One Render web instance and a passing readiness endpoint establish neither producer quiescence nor absence of in-flight leases. Inventory active worker processes and versions, additional services and schedulers, inbound webhooks and producer routes. Before cutover, stop claiming and accepting new work or buffer it durably, record affected queue counts and oldest outstanding leases by scope and type, drain work, and reconcile all unresolved provider outcomes. Require two independent observations across the maximum lease and retry window or an equivalent fenced lease proof. |
| Preservation | Take a coherent recovery point with the matching application and schema revision. Verify the expected table inventory and exact frozen-point row fingerprints, SQLite integrity, foreign keys, audit chain and links. The synthetic restore comparator and approximate live row-count tolerances are insufficient to certify migration equality. Rehearse both same-scope contention and successful cross-scope insertion with independent WAL connections, plus busy handling, interruption, disk pressure, restart and nested rollback. |
| Rollback | Before the first scoped-only write, prove compatibility and data equivalence with the old binary. After scoped duplicate literals exist, keep compatible binaries available and prefer forward repair that retains all writes. A rollback or snapshot restore requires its own approval, a post-snapshot delta plan and exact re-verification. Never delete or rewrite records to force old uniqueness. |
| External effects | Record effect identity, tenant, job, stable provider idempotency key, outcome and provider receipt. Maintain ambiguity holds for payments, messages, publishing and similar effects. Preserve inbound deliveries across the pause with approved buffering and deduplication. After recovery, reconcile effect receipts and webhook offsets before enabling workers. A queue lease expiring or a job missing after restore cannot itself authorise replay. |

No production queue state, worker inventory or migration preconditions were certified in this round. Execution requires owner approval, an approved maintenance window, rehearsed recovery with measured RPO/RTO, and documented evidence for each gate.
