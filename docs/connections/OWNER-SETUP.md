# Owner setup and deployment acceptance

This candidate is not deployed. Do not rotate existing secrets or reset the production database. Keep the existing Render disk and configuration. Review the patch and tests before the owner’s manual deployment.

## Platform administrator — once per provider app

1. Confirm the exact candidate commit, backup/recovery readiness and the same Render service. Keep auto-deploy disabled.
2. Keep the existing integration encryption key and session secrets. Replacing them can make existing encrypted credentials unreadable or invalidate sessions.
3. Register/verify the platform OAuth apps. Supply missing X and Snapchat app credentials through the existing secure hosting configuration. Do not place values in chat or Git.
4. Register the exact redirect URI generated by each connection’s Authorise endpoint. Existing configured redirect URIs must point to a supported callback on this deployment. Google, Meta and TikTok can use the supported shared/legacy callbacks. Do not infer that an app registration alone grants production API access.
5. Enable the required Google APIs. Request the actual provider scopes/products needed for the intended subscriber features. TikTok `user.info.stats` needs app approval before adding it to configured scopes and asking subscribers to consent again. Snapchat Marketing scope alone does not enable Public Profile statistics.
6. Meta/WhatsApp inbound events use the existing platform Meta app webhook and must be subscribed for the subscriber WABA/phone. The subscriber’s selected phone controls outbound replies; do not substitute a global phone/token.

## Each subscriber — inside their own workspace

1. Open Setup & Trust → Connections. For OAuth services choose Connect, sign in only on the official provider page, and consent to the account/resources they own or administer.
2. Return to Connections, choose Test connection, inspect any partial service errors, select the intended resources and Save selection. Google choices also feed the SEO workspace.
3. Choose Refresh figures. Check resource identity, reporting period, source, timestamp and unavailable/stale notes. Refresh has a five-minute cache; some provider reporting is delayed.
4. For business email choose Set up my email / SMS → Resend. Use a workspace-owned key with permission to read domains and send, plus a verified sender email. The key is write-only. Existing Gmail/Outlook mailbox access is a separate integration, not provided by this form.
5. Configure the displayed workspace Resend webhook URL in Resend. Add its signing secret through the same secure setup form. Receiving needs a Resend Receiving domain/subdomain; do not replace the MX records of an existing mailbox without a deliberate mail-routing plan. Enable the relevant sent/delivered/opened/bounced/failed/complained/received events. A verification test does not send mail.
6. For SMS use a workspace-owned Telnyx API key and an owned number in international format. Configure its messaging profile and displayed workspace webhook URL, then add the Ed25519 public key. Delivery charges and messaging eligibility remain provider-controlled. Verification does not send SMS.
7. For Website save the public HTTPS domain, add the unique `_superpro` TXT proof in the domain dashboard, then Verify website. Embed a form posting `name`, `email` or `phone`, and `message` to the displayed workspace endpoint. Keep the honeypot `website` field empty. This records enquiries, not page views.
8. Use Troubleshoot for a redacted error reference and next steps. App approvals, MFA and revoked consent require the account/platform owner to act.

## Live acceptance after manual deploy

Use two separate test subscriber workspaces and accounts. Preserve the existing Fleet Parlour TikTok connection. Only the owner should authorise any paid or externally visible test message.

- Verify the deployed commit before testing. Visit Connections directly by its current hash.
- Complete a Google OAuth round trip including provider denial/cancellation, and a TikTok round trip through its registered callback. Confirm old tokens/resources from another workspace never appear.
- Test each authorised provider, inspect the correct account, save resources and compare available figures against its provider dashboard, allowing reporting delays/rounding.
- Confirm the owner/admin can save credentials; a manager/worker cannot save or read credential values. Change workspaces and verify no form or resource draft carries over.
- With explicitly approved test deliveries, verify own sender/number, delivery receipt and inbound routing. Replay a signed event and confirm idempotency. A forged or other-workspace event must not change any records.
- Disconnect one workspace and confirm its connected actions stop without disconnecting another workspace or sibling provider.
- Re-test phone, tablet and laptop views in the production browser; confirm there are no new server errors. Record real evidence rather than marking every provider passed merely because configuration exists.

If a release issue occurs, the owner can restore the previous deployed source using the established Render procedure; additive OAuth session storage must not be dropped from the production database as part of routine rollback.
